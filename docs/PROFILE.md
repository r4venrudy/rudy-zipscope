# ZIP profile v1

The format reference is [PKWARE APPNOTE 6.3.10](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT). This document describes an intentionally conservative investigation profile, not full specification conformance or an emulator for every ZIP consumer.

- One disk, one unique EOCD candidate whose declared comment ends exactly at source EOF. Trailing data and competing exact-ending candidates are unsupported. The bounded backward search covers the maximum ordinary comment range.
- ZIP64 EOCD/locator records are supported when legacy sentinel fields require them. Record lengths/locations, disk counts and non-sentinel legacy values must agree. ZIP64 end extension data is bounded to one MiB. Multi-disk ZIP64 entry disk-start sentinels are outside this version.
- Central record count/size must match exactly. Names are nonempty and at most 4 KiB. Extra records have bounded TLV lengths and unique IDs; ZIP64 expanded fields are read in sentinel order. Unknown extra metadata is retained only for interpretation within the documented features, not comprehensively validated.
- Absolute local-header offsets are used as declared. Local version-needed, flags and method must match the central record. Non-streaming sizes/CRC must agree, with local ZIP64 expansion where needed. Streaming placeholders may be zero or consistent actual values. Four signed/unsigned and 32/64-bit descriptor layouts are tried; exactly one must match. A valid archive that remains ambiguous under this conservative rule is incomplete.
- Version-needed values above 4.5 are unsupported. Stored and raw DEFLATE methods are implemented. Encryption/patching/strong-encryption/masked-header flags, other compression methods, AES metadata and extended-language encoding metadata are unsupported. This is not a full validator for every version/date/unused metadata field.
- Referenced local/header/data/descriptor intervals cannot overlap each other or the central directory. Unreferenced spans before/between local records or between the directory and end records are hashed and flagged. A self-extracting-style prefix can be reported when declared absolute offsets are already coherent; no hidden offset adjustment or heuristic resynchronization is performed.
- Every supported payload must end at the compressed boundary, expand to the declared size and match CRC-32 before `verified` becomes true. SHA-256 identifies decoded contents independently of representation. A failed entry can retain a computed digest but remains unverified; later entries may be unvisited.

## Names and destinations

Raw central/local names remain separate. Flagged UTF-8 must contain valid scalar values without C0/C1/DEL controls; unflagged raw names must be ASCII. CP437 and other legacy decoding are unsupported. CRC-qualified Info-ZIP Unicode path alternatives are UTF-8 regardless of the ordinary name's encoding flag. Invalid Unicode metadata is not silently trusted; differing valid alternatives are error findings and are audited too.

Portable projection replaces backslashes with slashes, removes repeated separators and `.` segments, and **preserves `..`** for explicit traversal evidence. It reports absolute names, parent segments, colons/drive/stream syntax, Windows devices, trailing dots/spaces, Windows-invalid punctuation and empty paths. Exact/ASCII-case projected collisions and file-as-ancestor conflicts are reported. Non-ASCII names receive an explicit warning because full Unicode case folding/NFC equivalence is not modeled.

Unix creator hosts 3/19 use mode type bits to identify directories, symlinks and special files; DOS directory attributes are also observed. Type disagreements and nonzero directory content are flagged. Symlink target text is bounded to 4 KiB, checked as text, and modeled for escape/cycle observations without creation or following. Conservative parent-target checks can flag benign layouts. Current directory trees, existing filesystem objects, mounts, Windows reparse points, extractor overwrite order and arbitrary extra-field semantics are not simulated.

Namespace work stops after one million component/ancestor steps and findings are deduplicated while generated. Link reachability is memoized. Exceeding supported budgets means incomplete analysis, never a clear gate. Nested ZIP payloads are treated as content bytes, not recursively analyzed.
